      How the CSV is read
      
      
      One row per transaction or per customer, it does not matter which: rows that name the same taxpayer are added together, because a summary list carries one line per customer or supplier for the month. The records are then written in alphabetical order by name, which is what the regulation requires.
      
      
      Only the TIN column must be present. Everything else is matched by heading — the usual spellings used by spreadsheets and accounting packages are understood — and a missing figure counts as nil. Title rows above the headings are skipped, blank rows are dropped, short rows are padded, and comma, semicolon, tab and pipe separated files all read. Amounts may carry a ₱, PHP or Php marker and thousands separators.
      
      
      A company is named by its registered name and an individual by surname, first name and middle name. One record carries one or the other, never both. If your CSV has a single name column, write an individual's name as SURNAME, First Middle — the comma is how the tool knows where a surname like DELA CRUZ ends, and without it the row is refused rather than guessed at.
      

      
      What is checked before anything is written
      
      
      Every field of every record is checked against the layout, and the file is written only if nothing fatal is found. If something is wrong you get a list of rows and columns to fix, not a file that looks finished and is not.
      
      
        
        
      • Each TIN is exactly nine digits, is not your own, and is not a run of one digit.
        • 
        
      • A purchases record names a supplier and gives an address; a sales record may leave the TIN empty for an unregistered buyer.
        • 
        
      • Each record has exactly the number of fields its layout calls for, and no value is longer than its field.
        • 
        
      • No value contains the field separator, the enclosing quote, a line break, or any of the characters the Bureau's validation module refuses.
        • 
        
      • Amounts carry two decimal places with no separators, nil is written the way the format wants it, and the header's totals equal the sum of the detail records exactly.
        • 
        
      • The tax month is the last day of the month, on every record, with leap years handled by the calendar.
        • 
      
      

      
      
        Assumptions & settings
        
        
          
      • Value-added tax at 12% is used only to check that a tax column is consistent with its taxable column, never to work the tax out. A figure more than ₱1.00 away from the rate is remarked on, not refused, because a party may be partly zero-rated or exempt. The rate is one named constant and can be overridden.
        • 
          
      • Amounts are held in whole centavos, so the header's totals are exactly the sum of the records with no drift.
        • 
          
      • Negative amounts are refused by default, because the list has no column for one. Net returns and credit memos against the month's figures.
        • 
          
      • Text is upper-cased and accented letters are folded, because the file is a single-byte file and the Bureau's own entry screens upper-case what is typed into them. Ñ is kept, because the validation module makes an exception for it.
        • 
          
      • The ampersand becomes the word AND and the apostrophe is removed, because the validation module refuses both — and every such change is reported against the row it came from.
        • 
          
      • A branch code is not written anywhere: this file format has no field for one. If your CSV carries one it is read, reported and dropped.
        • 
          
      • Statutory provisions are cited as they stood when this was written. Confirm the current format and rules with the Bureau of Internal Revenue before you file.
        • 
        
      
      
      

      
      This tool builds a file from figures you give it. It does not check them against your books, your returns or your invoices, and it is not tax, accounting or legal advice. Run the file through the Bureau's own validation module before you submit it, and confirm the current format and the submission channel with the Bureau or a qualified practitioner.
